# E4 并发与 PCIe 饱和实验报告

## 结论摘要

在本机 RTX 5090、PCIe Gen5 x16、Qwen3-30B-A3B-FP8 和固定 480-coordinate
remote 专家计划下，C1--C32 内没有观察到首个持续退化点。预注册判据要求 TPOT
相对每个独立进程的 C1--C4 基线升高至少 10%，且至少 4/5 个进程同意、连续三个并发档位
成立；32 个档位的同意进程数均为 0。

- TPOT：C1 为 62.57 ms（bootstrap 95% CI 61.34--63.04），C32 为
  60.68 ms（60.57--61.21），没有持续恶化。
- Decode 吞吐：16.06 token/s 增至 528.06 token/s，为 32.89 倍；并发为 32 倍。
- PCIe RX：0.253 GiB/s 增至 6.543 GiB/s，C32 仍在增长，仅为 Gen5 x16
  单向理论值 58.69 GiB/s 的 11.15%，不符合 PCIe 带宽饱和的“需求增加、带宽平台、
  TPOT 恶化”联合特征。
- GPU stall：GPM SM activity 从 2.38% 增至 20.86%，但 occupancy 仅约 2.29%。
  独立 NCU 诊断的 long-scoreboard stall 中位数为 C1 31.19%、C16 44.98%、
  C32 44.71%。远程访问延迟确实是 kernel 的主要 stall 来源之一，但 C16--C32 没有继续
  恶化，且没有转化为用户可见 TPOT 退化。
- CPU DRAM bandwidth：N/A。该 KVM 未暴露 uncore IMC PMU/内存控制器 PCI 配置，
  Intel PCM 报告 `no memory controllers found`。CPU busy 约 7.5%--7.8% 只能作辅助信息，
  不能用于断言 CPU DRAM 是否饱和。

因此，remote-read 的实测可扩展范围是 **C1--C32，且观测 PCIe RX 不超过
6.54 GiB/s**。本实验没有得到 C1--C32 内的 copy/cache break-even。保守部署策略是：
在 C32/6.54 GiB/s 以内继续 remote-read；超过任一已验证边界时视为未验证区域，切换到
copy/cache 或先扩展扫描。在线触发器应沿用本实验判据：TPOT 相对低并发基线持续升高
至少 10%，并连续三个流量档位出现，同时结合 PCIe plateau、CPU DRAM 和 GPU stall 判断，
而不是仅凭单个带宽计数器。

## 实验设计

### 系统与冻结输入

- GPU：NVIDIA GeForce RTX 5090，driver 595.71.05，最大 PCIe Gen5 x16。
- 虚拟化：KVM；CPU 侧固定 `taskset 0-13`，OMP/MKL 各 14 线程。
- 模型：Qwen3-30B-A3B-FP8，单 GPU，eager Decode，TRITON_ATTN。
- 专家计划：沿用 E3 在评价前冻结的计划，SHA256
  `69d625693e7bd31ce00b9847bcfa0c80ccb487e5c0da03f1c985276ebf1f99af`；
  48 层每层 10 个专家，共 480 个专家，映射远程集合 2,264,924,160 B。
- 路径：static-alias/original-VA `remote_only`；所有远程页在模型加载后审计为
  CPU resident，GPU/unknown bytes 均为 0；正式运行 H2D copy bytes 为 0。
- 冻结 workload：evaluation `short_dialogue`，每请求 128 prompt tokens、128 output
  tokens。5 个独立模型进程按 0/7/14/21/28 轮换同一冻结 prompt 列表，避免小 C 只由
  固定的少量 prompt 决定。

正式实验没有采用最初尝试的 512-token prompt：C32 对应约 2.06 GB KV，有效 KV
预留 2.2 GB 后只余约 0.5 GB HBM，Prefill kernel 无法执行。E4 关注 Decode 并发路径，
因此改用冻结的 128-token evaluation fixture；专家计划、Decode 输出长度和远程路径不变。
所有失败 preflight/smoke 均未进入正式数据。

### 扫描与重复

- 并发：每个整数 C1、C2、...、C32，不把 C 误作 Claim 编号。
- 重复：5 个独立冷模型进程，顺序为 asc/desc/asc/desc/asc。
- 每进程先运行 warm C32；每个正式 phase 排除首次完整 Decode 和 5 个 Decode warmup
  step，随后计时 121 个 one-token Decode step。
- 正式性能 run 采集 200 ms NVML PCIe RX/TX、1 s GPM SM activity/occupancy/GPU
  DRAM activity、1 s `sar` CPU utilization。NCU 使用独立 application-replay run，
  只采样 C1/C16/C32 的 8 个 fused-MoE kernel，NCU 时间不混入 TPOT。
- 连续退化判据：每个 block 的 C1--C4 TPOT 中位数作为基线；某 C 达到基线的
  1.10 倍，至少 4/5 block 同意，并连续 C、C+1、C+2 成立。

它们包含 PCIe 协议和少量非权重流量，应解释为 remote-read 物理流量估计，而不是可精确

C22 起 TPOT 从约 64 ms 降至约 61 ms，5 个 block 均出现，属于有利的 batch/kernel
调度区间变化，不是退化点。PCIe RX 随路由到远程专家的 token 组合而有局部波动，但
C28--C32 从 6.05 增至 6.54 GiB/s，没有形成高并发平台。

### GPU stall 诊断

| C | fused-MoE samples | kernel duration 中位数 | long-scoreboard | lg-throttle | mio-throttle |
|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 28.37 us | 31.19% | 1.47% | 0.65% |
| 16 | 8 | 138.14 us | 44.98% | 0.79% | 1.17% |
| 32 | 8 | 166.69 us | 44.71% | 0.63% | 1.13% |

long-scoreboard 明显高于两类 throttle，支持“kernel 等待长延迟数据”的解释。然而该值在
C16--C32 持平，SM activity 和吞吐继续增长，TPOT 没有恶化；所以这是 remote-read 的
延迟特征，而不是 C32 前出现的持续饱和拐点。

## 有效性与限制

1. `remote bytes` 来自 NVML PCIe RX 时间积分，不能精确排除控制流量；完整映射的
   2.2649 GB 是地址空间/placement 属性，不等于每 token 必读字节。
2. CPU DRAM bandwidth 在该 KVM 上不可观测。因此可以排除“PCIe 接近理论峰值并平台”，
   也能看到 GPU long-scoreboard stall，但不能严格排除主机 DRAM 在某些访问模式下的影响。
3. 结论只覆盖 128-token prompt、128-token output、Qwen Track A 固定计划和 C1--C32。
   超过 C32、不同 prompt/KV 压力、不同计划或多 GPU 必须重新测量。
4. GPM 为 1 s 粗粒度采样，低并发 occupancy 会量化到接近 0；kernel stall 的归因以独立
   NCU 样本为准。

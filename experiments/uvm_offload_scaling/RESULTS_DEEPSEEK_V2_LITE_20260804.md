# DeepSeek-V2-Lite 卸载量与自动扩缩容实验

实验日期：2026-08-04

## 实验配置

- GPU：NVIDIA GeForce RTX 5090，32607 MiB
- 模型：`deepseek-ai/DeepSeek-V2-Lite-Chat`，BF16
- 数据集：ShareGPT，同一份 160 请求 fixture，四个 case 的 SHA-256 完全一致
- Prompt：320–360 tokens
- 输出：每请求固定 32 tokens
- 并发量：64、96、128、160
- 每个主阶段前均完成预热；模型加载、预热和扩缩容维护时间不计入阶段生成时间
- 固定卸载：启动时分别卸载约 4/7/10GB
- 自动扩缩容：64/96 并发卸载约 4GB，128 并发前增加至约 7GB，160 并发前增加至约 10GB
- 原始结果目录：`/tmp/deepseek_offload_scaling_20260804_221556`

| 初始化至约 4GB | 9 | 2528 | 1.9683 s | 成功 |

| 7GB 增加至约 10GB | 7 | 5664 | 1.5593 s | 成功 |

如果将调整耗时计入整个四阶段序列，自动方案的聚合吞吐会从 `233.1506 tok/s` 降至 `215.4043 tok/s`，下降约 `7.61%`。

## 关键对比

- 自动方案相对“始终卸载 10GB”在 64、96、128 并发分别快 `2.279x`、`2.262x`、`1.402x`；到 160 并发时两者基本相同。
- 固定 4GB 的四阶段聚合吞吐为 `361.3237 tok/s`，固定 7GB 为 `232.6708 tok/s`，固定 10GB 为 `162.9133 tok/s`，自动方案为 `233.1506 tok/s`。
- 卸载越多，远程读取的专家权重越多，吞吐下降明显。自动扩缩容的价值是仅在 KV 容量需求升高时增加卸载，避免低并发阶段提前承担 10GB 卸载的性能代价。
- 该负载下固定 4GB 即使在 160 并发也能完成全部请求并获得最高吞吐；这不代表更长 prompt、更长输出或更高并发仍有足够 KV 容量。

## 完整性校验

- 四个 case 均返回 `status=ok`、返回码 0。
- 每个 case 均完成 64/96/128/160 个请求。
- 每阶段输出分别为 2048/3072/4096/5120 tokens，无缺失请求。
- 自动模式 23 个 wave 全部成功；每个 wave 均在 26 个 MoE 层各释放一个专家，没有缺失层。
- 四个 case 峰值显存均为约 32110 MiB，这是 vLLM 预留分配器的进程峰值；实际物理用途通过 expert plan 和 KV target blocks 区分。
- 当前仅执行每个 case 一次，趋势明确，但若用于论文中的误差条/置信区间，应再执行至少 3 次独立重复实验。
